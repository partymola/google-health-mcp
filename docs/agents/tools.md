# Tools, their arguments and their replies

Part of the agent guide: [AGENTS.md](../../AGENTS.md) says when to read this file.

- **Tools**: `tools/` - domain-grouped modules; `sync_tools.py` also exports `auto_sync_if_stale(*data_types)`. A module reaches the wire only by being imported in `cli.py`. **`health_get_ecg` returns a reading's waveform only when asked for it**: thousands of voltages is a useless tool response and an expensive one, so the default carries the summary plus a sample count, which is `null` rather than 0 where no trace was stored. That is a constraint on the tool, not on what is cached. Pinned by `TestTheWaveformStaysBehindItsFlag` in `tests/test_rhythm.py`
- **An enumerated argument is constrained in the annotation, so the server refuses before any body runs.** `health_trends` takes `TrendType` and `TrendPeriod`, not `str`, and the class this closes is a wrong answer rather than bad input: unconstrained, `period` falls through to `_get_period_key`'s trailing `else`, so an unrecognised value returns twelve months of correct **monthly** figures under `"aggregation": "<whatever was sent>"`. Real data, no error, nothing empty: the shape nothing looks at twice. **Do not move either check inside the tool**: an in-body check reaches only the caller who already made the call, while the schema is what a model reads before deciding what to send. `TrendType` is unpacked from `_TREND_FNS` (`Literal[*_TREND_FNS]`) rather than written out, so the schema cannot drift from what the tool can answer. Hand-writing a complete list breaks nothing on the day it is written, and `TestTheDispatchesCoverEveryAcceptedType` is what fails once it drifts. Two copies stay outside that: the docstring's `Options:` lists, pinned back to the enum by `TestTheDocstringOffersWhatTheSchemaAccepts`, and the README's prose, which is not pinned at all. `TrendPeriod` has no dispatch to unpack, so the property is pinned instead of the list: `TestEveryAcceptedPeriodBucketsDifferently` fails if a value is added to it and not to `_get_period_key`, which is the same defect one line along. All of it in `tests/test_argument_validation.py`, which drives the **registered** tool through `mcp.call_tool`, the only layer that applies the schema, so a test calling the function directly passes whether the constraint is there or not
- **An open-set filter is checked against the cache instead, because Google names the workouts and this package cannot.** Unchecked, an `exercise_type` for `health_get_exercises` that matches nothing answers `No exercise entries found for this period`, which reads as a period without workouts rather than as a filter that cannot be used, so the model stops instead of retrying. A `Literal` is the wrong mechanism here: the accepted values are whatever the cache holds, and a new workout name would be refused by the schema. So the filter is matched, as a case-insensitive substring, against `db.exercise_names`, and a value none of them contain raises `UnknownExerciseType` naming them. **The message says the cache, and the hint about re-fetching is appended by `require_auth` rather than written at the raise site.** A refusal is raised rather than returned, so it never reaches `_annotate_offline`, which is what corrects that hint in a response body. Written at the raise site, the hint would tell the model on a reader host to try a live fetch that is disabled there. The exception asks for the hint through `wants_live_hint` and one place chooses the wording, so a second raise site cannot acquire a copy that offline mode fails to correct. Appending rather than rewriting a finished message also keeps the swap out of the echoed filter value and the cached names, which are the caller's text and the provider's. A name absent from the cache is not a workout the person has never done: the window may never have been synced, `auto_sync_if_stale` swallows its failures, and `_days_another_provider_recorded` skips a Google workout falling on a day an import already filled. Saying "you have not logged that" would be the same false confidence the empty answer gives, with the way out removed, and `test_the_refusal_is_about_the_cache_and_keeps_the_way_out` is what stops it coming back. It also puts stored workout names into an error, which the leak rules in [AGENTS.md](../../AGENTS.md#what-may-leave-the-process) permit here and nowhere by default: whatever their provenance, and `importer` writes a name straight from an export file, they are labels rather than measurements. **The refusal does widen the scope**, naming every distinct name in the cache where an ordinary response carries only the window asked about. That is accepted because the reader is the model, which can widen the window itself; it is not a precedent for a message that reports data outside what was asked for. **The fold has to happen in Python, and `db.query_exercises` therefore matches names exactly**: SQLite's `LOWER` covers ASCII alone, so folding in SQL over the caller's own spelling accepts `LÄUFEN` at the match and returns nothing from the query, which is the defect back. **The vocabulary is the whole cache, never the window**: a cached name outside the dates asked about is a true empty answer, and an empty cache refuses nothing because there is nothing to name. All of it in `tests/test_exercise_type_filter.py`, whose calls go through `mcp.call_tool`; the non-ASCII case is the only input that tells the two folds apart
- **A date range that cannot be queried is refused, never answered.** A start after the end, and a value of the right shape that is no date (`2026-13`, `2026-02-30`, a count of days past year 1), raise `InvalidDateError`, because an empty answer reads as a period without data and a bare `ValueError` reaches the caller masked. A missing start counts back from the end date or today, whichever is earlier: from today alone, an end in the past would be refused over a start the caller did not send, and from the end alone, an end after today moves the span forward with it, past today altogether once the end is more than the default span ahead. Every pattern must match the whole value, so a trailing newline is refused, and `parse_date` reads today once, so `0d` across midnight is not. Every date tool parses before it syncs or opens the cache, so a refused date costs no request; `health_trends`' `compare` parses its periods in `_compare_ranges` before the sync too, each matched whole with a day count of at least 1 and both counted from one reading of today, and with `compare` set the tool's own dates are not parsed at all. Pinned by `TestParseDate` in `tests/test_helpers.py`, `TestParseCompareRange` and `TestComparePeriods` in `tests/test_analysis.py`, and in `tests/test_date_ranges.py` by `test_every_date_tool_refuses_a_bad_range_before_any_sync`, which reaches every registered tool taking a `start_date` through `mcp.call_tool`, and `test_a_bad_compare_period_is_refused_before_any_sync`. Their cache stub raises `pytest.fail`, a `BaseException`, because `auto_sync_if_stale` swallows every `Exception` and a stub raising one would pass a tool that syncs first (`test_the_stub_raises_what_a_sync_cannot_swallow`)
- **Helpers**: `helpers.py` - `require_auth` (auth-gate decorator on every tool), plus `format_response`/`parse_date`. Every tool reply is compact JSON, including the ones `require_auth` re-serialises to add the offline or authorisation note, since indented output grows with the square of a reply's nesting and a broken or hostile reply reaches megabytes: `test_a_reply_is_its_compact_json` and `TestTheAnnotatedReplyStaysCompact` in `tests/test_helpers.py`. **`require_auth` is the one place an exception that *escapes* a tool keeps its message.** (`run_sync` also returns `str(e)` inside its own payload, which is a different route and is governed by the leak rules in [AGENTS.md](../../AGENTS.md#what-may-leave-the-process).) `mcp` 2.1 keeps a `ToolError`'s text and replaces every other exception's with `Error executing tool <name>`, so a `GoogleHealthError` is converted and nothing else is. The split follows those rules: this package writes the messages it raises deliberately, while an unplanned failure's text is exactly what must not travel, since a filesystem error on the token file or the cache names an absolute path. **Never widen the conversion to `Exception`**: it would undo that in one line. The converter also composes the re-fetch hint, appending the live or the offline wording by mode to an exception whose class sets `wants_live_hint`, because a raised message never reaches the response path that corrects that hint; the reasoning is under the exercise filter above, and `test_the_refusal_does_not_offer_a_live_fetch_offline` is what holds it. `HealthOfflineError` keeps a clause before it, because offline mode answers with one clean message rather than an error. Pinned by `TestWhichErrorsAreExplainedToTheModel` in `tests/test_tools.py`, in both directions: `test_an_unplanned_error_is_left_to_be_masked` is the half that fails if the conversion is widened, and it is why that test exists rather than only the one asserting a message survives. **Membership in the base is not a promise about the message**, and one raise site shows why: `_load_google_client` interpolates the resolved client path into a `TokenRefused`, which is deliberate for `google-health-mcp auth` where that path is the useful part, and is kept off the wire by `google_get` catching that type and re-raising `HealthAuthError`, pinned by `test_neither_message_carries_the_original`. A tool calling `refresh_google_token` directly would publish it
- **Every tool is registered with `@mcp.tool(structured_output=False)`**, because a `-> str` tool otherwise also sends its reply as escaped structured content, which a client may show the model instead of the text: `test_no_tool_declares_an_output_schema` and `test_a_tool_reply_is_its_text_alone` in `tests/test_tool_results.py`
- **Every empty answer from a tool taking `live` goes through `helpers.empty_answer`**: the tool's own note ("Requires sleep tracking.") always, and `LIVE_HINT` only after a cache read, because `live=True` has just re-fetched the window and offering it again sends the model to repeat the call. Offline, `_annotate_offline` swaps `LIVE_HINT` for `_OFFLINE_HINT` and keeps the note, since a reader host cannot fetch but the note still holds; a hint still naming `live=True` after that swap is replaced whole. Pinned by `test_an_empty_live_answer_does_not_offer_the_call_just_made`, `test_an_empty_cache_answer_offers_a_live_call`, `test_an_empty_answer_offline_keeps_the_note_and_drops_the_live_call` and `test_an_offline_hint_naming_live_in_other_words_is_replaced_whole` in `tests/test_empty_answers.py`, whose list `test_every_tool_with_a_live_flag_is_listed_or_excused` holds equal to the registered tools taking `live`
- **Every tool that reads the cache closes its connection in a `finally`**, so a read that raises closes it there rather than whenever the traceback is freed. Pinned per tool by `test_a_failing_cache_read_closes_its_connection` in `tests/test_connections.py`, whose list `test_every_tool_with_a_live_flag_is_listed` holds equal to the registered tools taking `live`, so a new tool taking `live` fails until it is added. `health_trends` is pinned separately in `tests/test_analysis.py`. `health_get_exercise_route` and `health_get_lifetime_stats` take no `live` and close in a `finally` too, and no test pins either. `db.get_db` itself closes the connection and re-raises when the schema or a migration fails, interrupts included, since the caller never receives it: `test_get_db_closes_the_connection_when_the_schema_cannot_be_applied`
